# ShedTrace Dashboard

ShedTrace is a student IoT capstone project that monitors microfiber shedding from washing machines using an ESP32 and a turbidity sensor. This project provides a simple Flask dashboard backed by Firebase Realtime Database.

## Features

- Flask backend with Firebase Admin SDK
- Live dashboard UI using plain HTML and vanilla JavaScript
- Circular microfiber threshold gauge
- KPI cards for total washes, lifetime captured mass, average mass per wash, and time since last wash
- Recent wash bar chart
- Combined history of wash and filter reset events
- Backend-controlled testing actions for simulated wash and filter reset

## Firebase setup

1. Create or open your Firebase project at https://console.firebase.google.com/.
2. Enable the Realtime Database.
3. Go to Project settings -> Service accounts.
4. Click "Generate new private key" and download the JSON file.
5. Save it as `serviceAccountKey.json` in the project root directory.
6. Make sure your database URL is in the format:
   `https://YOUR-PROJECT-ID-default-rtdb.firebaseio.com/`

## Required Firebase data model

The app expects the following database structure:

```
/devices/
  /shedtrace-01/
    /status/
      cumulative_mg
      filter_full
      last_updated
    /washes/
      pushId:
        timestamp
        estimated_mg
    /resets/
      pushId:
        timestamp
```

## Local environment configuration

You can either set environment variables in your shell or create a `.env` file. Example:

```bash
export FIREBASE_DATABASE_URL="https://YOUR-PROJECT-ID-default-rtdb.firebaseio.com/"
export FIREBASE_SERVICE_ACCOUNT_PATH="/absolute/path/to/serviceAccountKey.json"
export DEVICE_ID="shedtrace-01"
export STATUS_THRESHOLD_MG="500"
```

You can also copy `.env.example` to `.env` and update the values.

## API endpoints

- `GET /api/status`
- `GET /api/washes`
- `GET /api/resets`
- `GET /api/history`
- `POST /api/simulate-wash`
- `POST /api/clean-filter`

## Testing actions

These are backend-controlled:

- `Simulate a wash`: generates a random 40-170 mg wash and pushes it to Firebase.
- `Clean filter`: resets `cumulative_mg` to 0 and logs a reset event in Firebase.

These actions are not performed directly from the frontend.

## Important note on data

The dashboard only displays data read from the Firebase Realtime Database. No hardcoded sample wash data is included in the project. The only simulated test data is generated by the backend via the "Simulate a wash" action.

If you want to differentiate test entries, the backend marks simulated wash events with a `source` value of `simulated` and the UI labels them as such.
